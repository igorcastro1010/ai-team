# V0.3 — GitHub App e desenvolvimento supervisionado

**Objetivo:** integrar a App própria ao repositório privado `igorcastro1010/ai-team`, sem herdar credenciais do CLI GitHub ou do Desktop.

**Decisão de implementação:** API REST oficial com httpx; JWT RS256 com PyJWT/cryptography. A chave vem exclusivamente do cofre. Tokens de instalação ficam somente em memória. Manter o executor textual da V0.2 separado de ações externas estruturadas.

## Etapas
- [ ] Testar e implementar autenticação da App, validação da instalação seletiva e consulta do único repositório autorizado. Homologar leitura real antes de habilitar escrita.
- [ ] Adicionar propostas persistentes de branch, commit de arquivo textual, issue e PR; aprovação explícita vinculada ao conteúdo, execução separada e auditoria. Impedir escrita em main, merges, exclusões, workflows e caminhos de credenciais.
- [ ] Expor revisão e resultados no painel, com confirmação e proteção contra submissão duplicada.
- [ ] Executar testes de autenticação, autorização, concorrência, erros e UI; homologar um fluxo sintético somente no novo ai-team, sem merge nem deploy.
- [ ] Documentar evidências e limitações; commits e pushes por etapa validada. Só concluir V0.3 com o fluxo operacional verificado.

## Contratos e riscos
`github_client.py`: origem fixa `https://api.github.com`, sem redirecionamentos, timeout, erros sanitizados, JWT curto e escopo mínimo por chamada. A instalação deve pertencer ao proprietário, usar seleção por repositório e conceder acesso somente a ai-team. Detectar seleção ampla antes de criar tokens de escrita.

Escritas exigem conteúdo revisável no banco antes da aprovação. Uma chamada com resultado incerto nunca será repetida automaticamente: marcar para reconciliação no GitHub. Validar política também no executor, mesmo se a proposta já foi validada pela API. Nenhuma credencial ou instrução livre chega aos agentes.

Revisar especialmente: instalação ampliada após homologação, estado de aprovação obsoleto, crash entre GitHub e persistência, paths com encoding/traversal e erro de API contendo segredo. O usuário admin local ainda está pendente; cenários automatizados usam proprietário e banco sintéticos, sem contornar o login de uso real.
